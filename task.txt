# DSS Project (Customer Churn DSS) — Development Tasks (Branch: BaoCao)

Goal: Upgrade the current system into a **real Decision Support System (DSS)** for **Telecom Customer Churn Prediction** using dataset `WA_Fn-UseC_-Telco-Customer-Churn.csv`.

Tech stack in branch `BaoCao`:
- Frontend: React + TypeScript (`frontend-react`)
- Backend: NestJS + TypeScript + MongoDB (`backend-nestjs`)
- ML Service: Python + scikit-learn + Flask (`ml-python`)

## 1) Decision Support (DSS) Features (Highest Priority)
### Recommendations (Business Rules)
- [ ] **DSS-01** Implement a **Recommendation Rules Engine** in backend:
  - Input: `churn_probability` + selected customer features (Contract, tenure, InternetService, MonthlyCharges, PaymentMethod, etc.)
  - Output: `recommendation`, `priority` (`LOW|NORMAL|HIGH|URGENT`)
  - Must be deterministic and documented (rule table in docs).
- [ ] **DSS-02** Add API response fields for DSS output:
  - `recommendation`, `priority`, `risk_level`, `churn_probability`
  - (Optional) `reason_codes: string[]`

### What-if / Scenario Simulation
- [ ] **DSS-03** Create **What-if Simulation API**:
  - Endpoint: `POST /api/predictions/what-if`
  - Body: `{ customerId?: string, baseCustomer?: object, changes: object }`
  - Response: `{ base: PredictionResult, scenario: PredictionResult, delta: { probabilityDelta } }`
- [ ] **DSS-04** Build frontend **What-if UI**:
  - Pick a customer (or use last predicted)
  - Change 1–3 fields (Contract, MonthlyCharges, InternetService, tenure)
  - Show before/after probability + risk + recommendation

### Explainability (Why this prediction?)
- [ ] **DSS-05** Add explainability output:
  - Option A (fast): global feature importance from RandomForest
  - Option B (best): SHAP values per prediction
  - Return `top_factors: [{ feature, value, impact }]` (top 5)
- [ ] **DSS-06** Frontend explainability panel:
  - Show top factors as bar chart
  - Short text: “Most influential factors: …”

## 3) Backend (NestJS) Tasks (`backend-nestjs`)
### Data Model & Storage
- [ ] **BE-01** Finalize MongoDB schemas:
  - `Customer` (fields matching dataset)
  - `Prediction` (customerId/ref, probability, risk, recommendation, createdAt, inputSnapshot)
- [ ] **BE-02** Store prediction history:
  - Every prediction call should insert into `predictions` collection
  - Link to customer if prediction is from existing customer

### Prediction Flow (End-to-End)
- [ ] **BE-03** Add endpoint to predict for an existing customer:
  - `POST /api/predictions/customer/:customerId`
  - Steps:
    1. Load customer from DB
    2. Map DB customer → ML input payload
    3. Call ML API `/predict`
    4. Apply recommendation rules
    5. Save prediction record
    6. Return result
- [ ] **BE-04** Add endpoint to predict from raw input (no DB):
  - `POST /api/predictions`
  - Validate payload, call ML, apply rules, save (optional)
- [ ] **BE-05** Add `GET /api/predictions/stats`:
  - Count by risk level
  - Last 7 days predictions (if timestamps exist)
- [ ] **BE-06** Add better error handling:
  - If ML API is down → return 503 + readable error
  - Log the request/response errors

### CSV Import
- [ ] **BE-07** Improve CSV import validation:
  - Reject missing required columns
  - Show how many rows imported / failed
  - Return details for failed rows
